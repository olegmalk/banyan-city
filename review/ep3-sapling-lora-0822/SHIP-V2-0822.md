# The sapling LoRA v2 — the dataset fix was measured, and it made things worse

**2026-08-22. $0. About two card-hours on a shared box.**
Steward's measurement. **Nothing here is a taste call and nothing has been
published** — every frame carries `approved: false` / `provisional: true`.

---

## The one line

**v2 is worse than v1.** Five of the pre-registered bars fail where v1 failed
three. The one axis the whole dataset was rebuilt to move — a figure in frame —
went **0/3 to 1/3**, a single frame. Identity lost two frames, leaf count lost
three, ground lost one.

Fifteen new frames carrying a figure and eleven named ground materials bought
one frame on the bar they targeted and cost six frames elsewhere.

**No shipping weight is sanctioned. v1 remains the better of two failures, and
neither is shippable.**

## What the dataset actually changed

59 frames against v1's 44, and **two new caption variables named in both
directions** so the trigger is excused from carrying either:

- **Figure presence** — `alone in the frame` on 44 frames, `with a small green
  goblin <where>` on 15. Eight were harvested from ep2 plates the tree already
  owned and judged; seven were built new (eight built, one dropped).
- **Ground material** — `rooted in <material>`, 11 materials, 17 non-grass
  frames. v1's captions had **no ground token at all**.

The two axes are **not confounded**: all four cells of figure × ground are
populated, so each was separately learnable. That was checked before training.

**No hyperparameter moved.** Same rank 32 / alpha 16, same learning rates, same
scheduler, optimizer, batch, base and seed. The only moved number is the repeat,
3 → 2, which holds total image passes at 1180 against v1's 1320 — within 11%.

## A correction to v1's own verdict, found while building this set

The v1 ship page says **"44 of 44 stand on grass."** Measured at the root point
on the plates themselves, **ten do not**: `s14/s15/s16` (u08) and `s19/s20/s21`
(r08) root on a bare dirt path, `s12/s13` (u07) on forest floor, `s36/s37`
(v05) on wet rock.

The set already carried four non-grass materials and **no caption had ever named
one**, because v1's scheme has no ground token. So B2_ground failed partly on a
*caption* gap and not only a pixel gap. That correction stands on its own and is
independent of this run's outcome.

## Why it got worse — four candidates, named and not ranked

This run cannot separate them, and picking one would be exactly the error this
lane keeps catching itself in.

1. **Caption dilution.** v2's captions carry two more clauses, so `bnysapling`
   is a smaller share of every caption **including all 44 that were previously
   fine**. The regressions are on the SUBJECT ITSELF (B1, B5) and they show up
   on frames the dataset did not otherwise change — which is what dilution
   predicts.
2. **Fewer passes per frame.** repeat 3 → 2 held total passes near v1's, which
   was right for attribution, and means each frame was seen twice per epoch
   instead of three times.
3. **Harder frames.** The 15 figure frames put a large, high-contrast,
   semantically dominant character beside a small plant, several times at the
   frame edge. A subject LoRA fed frames where the subject is not the salient
   object may simply learn a weaker subject.
4. **Epoch.** Only epoch 10 was graded; 2/4/6/8 sit on the box unexamined.

**The cheapest cut that separates (1) from (2) and (3) is one card-hour:**
retrain on the v2 *frames* with v1's *caption scheme* on the original 44, adding
the new clauses only to the 15 new frames. If B1 and B5 return to v1 levels the
cause is dilution and the fix is a shorter scheme. If they do not, it is the
frames.

## What went right, recorded so it is not lost in the verdict

- **The build pipeline worked end to end and every guard fired.** Eight plates,
  eight composites, eight naturalize passes, 59 frames staged with all 59
  sha256s verified and all 59 SDXL-provenance asserted — the item-18 gate, in
  code, zero mismatches.
- **Three frames were refused by checks rather than by eye**, before any GPU
  second: two on C5 (a green plant on bright pale ground reads as pasted) and
  one on C3 (a plant off the frame edge). All three were fixed by moving the
  root, found by a sweep that cost nothing.
- **One frame was predicted to fail and did.** g7's palette sampled ONE
  green-dominant pixel; the spec named it as the at-risk frame before the render
  and it was dropped after it, on D4.
- **`train-jerry-0820.yaml`'s `min_bucket_reso` landmine is fixed** — 1024 → 832,
  the same one-number assert that killed v1's first attempt in fifteen seconds.

## Governance

**DECISIONS.md item 18 is untouched and still open.** Zero LTX pixels entered
this run and that is enforced in code, not promised: every frame is an
animagine-xl-3.1 plate → a numpy composite → one 0.30 animagine inpaint, and the
stage step refuses any frame whose manifest does not assert that chain. The
steward is not closing item 18; this records scope.

**The weights ban held.** Five 228 MB checkpoints were written to the box's
farm-out and `git check-ignore -v` was run against them rather than assumed —
`.gitignore:96` catches them. Their sha256s are in `pipeline/lora/registry.yaml`
and the bytes stay on the box.
